# AGENTS.md — USSD ("Accessibility demo")

Context file for AI coding agents (and humans). Read this first, then follow the links.

## What this app is

A tiny Android app that lets the user save USSD / "quick codes" (e.g. `*100#`), tap one to dial it, and then
**reads the operator's reply out of the system USSD dialog using an `AccessibilityService`**, stores it next to
the code and dismisses the dialog. Launcher label: "Accessibility demo". Open source (MIT), single author.

- Package / applicationId / namespace: `com.tooploox.ussd` (**must never change** — it is the app's identity on Google Play)
- Language: Java (source/target 17), no Kotlin
- Version: `versionCode 3` / `versionName "0.3"` (last released: 2 / "0.2", git tag `0.2`)
- Single Gradle module; **the app module is the repo root** (no `app/` directory)
- No tests, no DI framework, no network access (no `INTERNET` permission)

## Commands

The Gradle JDK must be 17+ (17 minimum, 21 recommended; 25 was verified). No JDK 17/21 is installed locally, so use
Android Studio's JBR (JDK 25):

```bash
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
export ANDROID_HOME=$HOME/Library/Android/sdk      # or rely on local.properties (sdk.dir)

./gradlew assembleDebug      # -> build/outputs/apk/debug/ussd-debug.apk
./gradlew lintDebug          # fails on any finding not in lint-baseline.xml
./gradlew assembleRelease    # -> build/outputs/apk/release/ussd-release.apk; R8 on; signed only if the keystore
                             #    (~/.android/dmax.keystore or $KEYSTORE_FILE) and keystorePassword
                             #    (Gradle property or $KEYSTORE_PASSWORD) are both present, otherwise unsigned
adb install -r build/outputs/apk/debug/ussd-debug.apk
```

Emulator testing notes (observed on an API 37 emulator during the upgrade; not part of the build):
- `SetupActivity` is `exported=false`, so launch `UssdListActivity` instead
  (`adb shell am start -n com.tooploox.ussd/.ui.UssdListActivity`).
- The list screen redirects to `SetupActivity` unless `CALL_PHONE` is granted **and** the accessibility service is
  enabled. `adb shell pm clear com.tooploox.ussd` resets the accessibility setting; after installing/clearing,
  re-apply the secure setting if needed (`enabled_accessibility_services` =
  `com.tooploox.ussd/com.tooploox.ussd.accessibility.UssdAccessibilityService`, plus `accessibility_enabled 1`).
- A real USSD round trip needs a SIM device; it has not been tested.

## Working conventions for agents

- The project builds (`./gradlew assembleDebug`, see Commands). Do not downgrade the toolchain.
- Keep `applicationId`/`namespace` = `com.tooploox.ussd` and keep the class `com.tooploox.ussd.domain.Ussd`
  (fully-qualified name, fields, and the pinned `serialVersionUID = -2632603246578927450L`) unchanged: user data is
  stored as Java-serialized objects in SharedPreferences and is keyed to that class
  (see [docs/context.md](docs/context.md#persistence-gotcha)). `proguard-rules.pro` keeps the class for R8.
- Never commit signing secrets. Release signing uses `~/.android/dmax.keystore` (not in repo) and the
  `keystorePassword` Gradle property (put it in `~/.gradle/gradle.properties`) or `KEYSTORE_PASSWORD`.
- Local environment facts (checked 2026-11-17): JDK 25 only (Android Studio JBR), Android SDK at
  `~/Library/Android/sdk` with platforms `android-36`, `android-37.0` and build-tools `36.0.0`, `37.0.0`.
- Code style in repo: 4-space indent, Java, lambdas allowed, file header comments with author/date.
- New lint findings fail the build; either fix them or (deliberately) extend `lint-baseline.xml`.
- When you change architecture, update [docs/architecture.md](docs/architecture.md). When you complete a
  migration step, tick it in [docs/upgrade/05-plan-and-verification.md](docs/upgrade/05-plan-and-verification.md).

## Known quirks (short list — status table in docs/context.md)

Open:
1. Core feature depends on an OEM/system dialog (`com.android.phone`, view ids `android:id/message` and
   `android:id/button1`) — fragile across Android versions and vendors; not tested on a real SIM/OEM device.
2. The UI has no way to delete a saved code (`UssdRepository.removeUssd` exists but nothing calls it).
3. The add-USSD dialog does not auto-focus the input / show the keyboard. (On an API 37 emulator, Gboard's phone
   dialpad did not type `*`/`#`; on the maintainer's physical phone Gboard types them fine, so nothing was changed.)
4. Material 3 default colours changed the look (the app never defined brand colours).
5. `UssdRunner` pending state is in memory only and expires after 30 s (a reply after process death or later
   than 30 s is not captured and the dialog is not auto-dismissed); `run` silently returns when `CALL_PHONE` is
   missing. Tiny gap: if the window expires between the service's `hasPending()` check and `setResponse()`, the
   service still fires the refresh event and clicks the dialog without storing the reply.
6. `lint-baseline.xml` holds 10 deferred findings (see docs/context.md).

Fixed in the upgrade (history kept in docs/context.md): service NPEs / acting on any phone dialog, null entries and
unstable order in the stored list, manifest `exported`/`package`, proguard copy, `POLICY.md`, stray `res/res/`
(unreferenced alternate renderings of `ic_enabled`/`ic_disabled`; still in git history), keystore property.
